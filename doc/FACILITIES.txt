# Facility numbers of the StarLet-based projects - the one registry
#
# A condition value is $DEFFAC(facility) | $DEFMSG(message) | $DEFSEV(severity):
# the facility number takes bits 16..31, so 0x0001..0xFFFF.  Two facilities with
# the same number give the same condition values - the wrong message text, wrong
# matches of a status.  A number is taken here BEFORE it goes into code.
#
# New facility: take a free number (the blocks below), append a line in its
# block keeping the order, then put the number into the project's catalogue
# header with a comment "see utility_routines/doc/FACILITIES.txt".
# Never reuse a number of a retired facility: mark the line "retired".
#
# Blocks (by habit so far, not a rule of the code):
#	0x0001..0x00FF	StarLet itself and the old decimal numbers (TTR 135, T2R 138, TPU 0xAB)
#	0x0100..0x01FF	system tools and emulators (HELP, SEARCH, vBACKUP, skshow, MSCP-Hub, IA64)
#	0x0800..0x09FF	daemons (BATCH, yaVNA)
#	0x0A00..0x0BFF	applications (yaVTERM, ACS, BroTwins)
#	0x07F0..0x07FF	tests only, never in a product
#
# Columns: number, facility (the $FAC prefix), project, where it is defined, notes.
# Last checked against the code: 17-NOV-2026 (grep of /root/Works for FACNO/$DEFFAC/#define <FAC> n).
#
